## Why

GPU Cloud Provider Setup is already defined as a critical flow, but the native layer currently does not implement the durable provider setup workflow. This change establishes the first native-owned credential and provider setup path so later Workspace Setup and Workspace Provisioning flows can rely on authoritative provider state.

## What Changes

- Add native commands for reading redacted GPU Cloud Provider Setup status and submitting one provider setup request.
- Persist mutable provider setup metadata in SQLite while storing Provider API Keys only in the secure keyring.
- Introduce a small native GPU Provider abstraction for provider-specific key validation, with RunPod as the v1 implementation.
- Validate RunPod keys through an identity-focused GraphQL `myself` request and derive redacted setup metadata from the response.
- Return only UI-safe redacted setup data to React; do not include a validation status field in the command contract.
- Reject repeated setup after a complete setup exists.
- Attempt recovery when a provider key exists in keyring but SQLite setup metadata is missing by validating the existing key before treating setup as unavailable.
- Preserve the existing provider scope: v1 supports RunPod only.
- Preserve the existing execution model: no local ML inference and no hosted LumaForge backend.
- Do not implement Factory Reset or Workspace cleanup in this change beyond respecting their recovery boundaries.

## Capabilities

### New Capabilities

- `gpu-cloud-provider-setup`: Native-owned setup, validation, persistence, redacted status, idempotency, and recovery behavior for the default GPU Cloud Provider.

### Modified Capabilities

- None.

## Impact

- `src-tauri/`: new native domain, application service, provider abstraction, RunPod provider implementation, SQLite persistence, keyring infrastructure, command adapters, generated binding types, and tests.
- `src/generated/commands.ts`: regenerated by `tauri-specta` after native command contract changes.
- React command usage can switch from placeholder commands to generated setup commands, but durable provider setup state remains Native-owned.
- Dependencies already listed in `src-tauri/Cargo.toml` are expected to cover this change: `sqlx`, `keyring`, `reqwest`, `secrecy`, `zeroize`, `tokio`, `thiserror`, `specta`, and `tauri-specta`.
